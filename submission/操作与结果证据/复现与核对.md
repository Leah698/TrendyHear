# TrendyHear v0.9.0 操作、可核对结果与失败状态

更新日期：2026-10-14。

## 1. 固定运行环境

- 应用：`skystream.trendyhear` v0.9.0。
- OctoSense：`desktop-v0.1.0-rc.6-3-g243ee8c8`。
- 本地独立测试壳：`build/install-0.9.0-local/OctoSense-Test-0.9.0.app`。
- 本地测试包使用既有测试签名密钥，不修改官方目录，不上传网络。

## 2. 一次操作与可核对结果

推荐录像和验收使用以下链路：

1. 打开听见顾问，输入一个具体成长目标和一条真实个人条件。
2. 核对顾问摘要，在 TrendyHear 确认卡片点击“确认保存”。
3. 等待 News 与 Opportunity 两条独立工作流结束。
4. 打开一条机会详情，核对来源链接、证据状态、日期和顾问分析。
5. 对满足日期规则的机会点击“加入听见日程”，核对日期依据后确认。
6. 打开听见日历，在对应日期读取同一标题和来源；重启应用后再次查看。

可核对结果包括：

- Goal Profile 中保存的是确认后的方向和引用，不是模型推测。
- 机会详情里的字段状态与来源原文一致。
- 顾问分析引用的个人背景能够在用户原话或已确认记录中找到。
- 日程保存前后事件编号、标题、日期和来源一致；重复操作不会产生第二条相同事件。
- 日期证据不完整时，“加入听见日程”不开放。

最终人工验收截图和录像必须来自同一个固定 v0.9.0 包。自动构造数据的回归只能作为补充证据。

截图文件、命名和证据对应关系见 [`screenshots/证据索引.md`](screenshots/证据索引.md)。在 `screenshots/真实运行/` 的四张最终截图齐全前，本节是验收步骤说明，不单独构成真实运行证明。

## 3. 失败状态记录

### A. MiniMax 语音生成未完成

**尝试：** 在 rc.6 中通过宿主 `model.audio` 请求 MiniMax `speech-2.8-turbo`，再保存和播放返回音频。

**实际结果：** 人工点击后生成等待时间很长，最终没有获得可播放的语音，界面显示语音不可用。宿主媒体用量记录说明请求进入过媒体路径，但该证据不能证明服务商完成合成。

**处理：** 不把语音写成已完成能力。v0.9.0 首页恢复“生成今日简报”，文字简报继续正常工作。语音尝试作为失败状态证据保留，后续需要单独核验 MiniMax API 音频权限、余额、响应错误和异步接口接入。

### B. OctoSense 系统 Calendar 跨应用执行未完成

**尝试：** 通过 OctoSense 内置 Calendar 创建事件，并按请求标识查重和读回。

**实际结果：** 受当前权限和 Shell 能力限制，无法形成可重复验收的跨应用创建与读回闭环。

**处理：** TrendyHear 增加听见日历，保留用户确认、日期证据、查重、保存和读回要求。机会页保留“打开系统日历”实验入口；补丁、方案和核验记录位于 `docs/platform-calendar/`，不得把入口存在描述为执行成功。

### C. 行动机会来源阶段曾持续加载

**触发：** 一次人工运行中“正在并行读取活动源”持续超过三分钟。

**原因：** 某些响应可能在解析时发生结构异常，旧实现会在递减待完成计数前中断，导致整体阶段无法结束。来源数量少不是这次卡住的直接原因。

**修复：** v0.9.0 将解析放入异常隔离，无论单源成功与否都更新计数；同时增加 12 秒单源上限、20 秒总上限和 `已完成/总数` 进度。固定包仍需人工复验实时网络表现。

### D. 桌面与移动抽屉界面实验未采用

**尝试：** 为桌面和手机宽度开发抽屉展开交互。

**实际结果：** 在当时宿主组件能力和移动布局下稳定性不足，继续使用会影响主流程。

**处理：** 正式 v0.9.0 使用“今日 / 兴趣 / 机会 / 历史”底部导航。实验补丁和说明保存在 `docs/experiments/navigation-drawer/`，不作为当前运行依赖。

### E. 后台定时抓取与提醒没有宿主权限

**尝试：** 在设定时间自动抓取新闻，并在应用关闭时继续发送简报或日程提醒。

**实际结果：** 当前 OctoSense 宿主没有向应用提供可验收的后台唤醒与通知权限，关闭应用后无法保证任务执行。

**处理：** 定时任务在应用打开时检查；错过后在下次打开时按当前规则补处理。界面和文档不声称应用关闭期间持续运行。

### F. UI/UX 多轮调整后仍有未达预期的细节

**尝试：** 围绕新闻卡片、内容间距、图片位置、文字层级和桌面／移动窗口布局进行了多轮测试与调整。

**实际结果：** 核心页面和主流程可以运行，但部分窗口尺寸下新闻卡片的内容间距仍显宽松，桌面端与 Android 的跨尺寸一致性也尚未完成真机验收，因此不能声称界面已经实现完整的自适应设计。

**处理：** v0.9.0 优先冻结稳定的底部导航和紧凑卡片结构，将剩余的信息密度与跨尺寸排版问题列为已知限制；后续依据固定包截图和 Android 真机结果继续调整。

## 4. 其他失败边界

- 未配置模型或服务商拒绝请求：显示失败并允许重试，不生成占位式 AI 结果。
- RSS 或活动来源超时：保留其他成功来源；全部失败时显示失败或空结果。
- 活动来源覆盖有限：空结果不代表互联网上不存在相关机会。
- 聚合目录中的资格、状态和日期：必须继续以官方页面核验，不能直接视为已验证事实。
- 活动规则未知：显示待核验或未知，不声称可以报名。
- 日期证据不足：不允许写入听见日历。
- 重复日程：复用已有结果，不重复创建。
- 本地存储失败：显示保存失败，不能继续宣称操作成功。

## 5. 证据边界

原生隔离回归使用构造数据调用正式函数，不请求真实模型和实时来源。App Hub 静态检查只证明包格式和策略检查通过。本地测试密钥签名只用于本机目录。真实模型、实时来源、人工界面、Android 和网络发布需要分别报告，不能相互替代。
