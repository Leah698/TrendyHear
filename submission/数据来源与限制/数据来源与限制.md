# TrendyHear v0.9.0 数据来源与限制

更新日期：2026-10-14。

## 新闻来源

应用通过 HTTPS 读取以下公开 RSS：

| 来源 | 方向 |
| --- | --- |
| 中国新闻网 | 时政、教育、社会、即时、国际、财经、文化 |
| IT之家 | 科技 |
| 爱范儿 | 科技与设计 |
| Solidot | 科技 |

新闻标题、摘要、发布时间、图片和原文链接来自订阅源。应用保留来源归属，不声称拥有第三方新闻内容，也不将 Apache-2.0 许可证扩展到新闻内容。

候选按链接或标题去重，再由宿主模型从当前来源中选择最多八条并生成 100–200 字文字简报。模型只能使用传入的候选事实；摘要仍可能遗漏上下文，用户应打开原文核对。

## 行动机会来源

| 来源 | 用途 | 证据边界 |
| --- | --- | --- |
| Hackalendar | AI、学生、创意、数据、全球线上与综合活动发现 | 目录线索，不自动视为主办方事实 |
| FOSS United Events | 开源社区活动 | RSS 线索，重要规则继续核验 |
| Conferencely / Symposia | 技术与学术会议 | 会议目录线索 |
| grants.watch | 研究资助 | 资助目录线索 |
| Jobicy | 远程实习 | 职位目录线索 |

多个来源并行收集，并轮询合并不同来源的候选。一个具体活动样本不会限制搜索范围。v0.9.0 设置 12 秒单源等待、20 秒来源阶段总等待，并隔离格式异常；超时或失败来源不会阻塞其余结果。

## 字段证据

活动名称、链接、类型、主题、报名状态、参与资格、活动形式、截止时间、作品要求和项目复用规则分别记录：

- `verified`：当前来源原文明确支持。
- `unverified`：有相关线索，但还未完成核验。
- `unknown`：没有获得信息。

模型不能把 `unknown` 补成肯定事实，也不能生成候选中不存在的官方链接。聚合目录提供的条目仍可能已过期、重复或指向非主办方页面；重要决定应打开来源核对。

## 个人信息与模型

应用向宿主模型发送完成当前任务所需的已确认兴趣、目标、可选个人背景、反馈和公开候选文本。个人背景必须引用用户原话或之前确认的记录。模型配置、密钥、费用和服务可用性由 OctoSense 宿主管理，应用不读取密钥。

## 日程与提醒

听见日历只接受完整 ISO 日期、日期与来源引文匹配、官方核验当前有效且报名状态为开放的机会。添加必须经过用户确认；应用查重、保存并读回后才显示成功。听见日历保存在应用目录，不访问设备日历。

系统日历入口属于实验功能，只尝试让 Shell 打开系统 Calendar，不传递听见日程。跨应用创建未完成验收。

曾尝试在应用关闭时继续执行定时简报和提醒，但当前 OctoSense 宿主没有向应用提供可验收的后台唤醒与通知权限。任务只在应用打开时检查，错过后在下次打开时按当前规则补处理。

## 失败与覆盖边界

- 网络故障、超时、限流或格式变化可能导致来源缺失。
- 没有机会卡片表示当前来源与过滤条件没有产生可展示结果，不表示互联网上不存在相关活动。
- 模型失败时不生成伪造简报或判断；已经成功的独立结果应保留。
- 活动资格或报名状态不明时，不宣称用户可以报名或符合资格。
- 自动检查不证明实时来源、真实模型质量、Android 真机或 App Hub 正式发布。

当前失败状态的操作和结果记录见 `submission/操作与结果证据/复现与核对.md`。
